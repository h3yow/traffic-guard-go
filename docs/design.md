# 入口流量防护 —— 成本加权、分组分层与运行期调整

本文档说明在原有“客户端限速/突发 + 全局在途 + 上游归类熔断”之上新增的三类能力：

1. 按**请求成本**核算准入（成本加权，缺省成本 1）；
2. 按**分组/租户**维度叠加额度（客户端 → 分组 → 全局三层）；
3. **运行期热调整**额度配置，不重启、不断服务，非法配置回退旧配置。

---

## 1. 计费口径：一切按“成本”累计

### 1.1 成本声明

- 配置 `endpoint_costs`：`入口标识 -> 单次成本`，成本必须为正整数。
- 请求可通过 `RequestInfo.Endpoint`（HTTP 入口取 `X-Endpoint-ID`，缺省用 URL 路径）
  命中声明；未声明或未携带标识的入口，成本一律按 **1** 计算（与旧口径完全一致）。
- 也可通过 `RequestInfo.Cost` 显式指定成本；显式值优先于 endpoint 声明。

```json
{ "endpoint_costs": { "/report/export": 8, "/report/query": 2 } }
```

### 1.2 三类额度都按成本累计

同一成本同时计入：

| 额度         | 窗口/口径            | 计数单位       | 归还时机             |
|--------------|----------------------|----------------|----------------------|
| 突发 `burst` | 滚动突发窗（100ms）  | 准入成本累计   | 不归还，随窗口滑出   |
| 速率 `rate`  | 滚动速率窗（1s）     | 准入成本累计   | 不归还，随窗口滑出   |
| 在途 `in_flight` | 瞬时（全局/分组） | 当前未结束成本 | 请求结束时按原值归还 |

判定规则（关键不变式）：

- 任意时间窗内“已用成本 + 本次成本”**超过上限即整体拒绝**，绝不只占用一部分。
- 被拒绝的请求**不产生任何记账**（窗口不追加、在途不增加）。
- 成功受理的请求在结束时**按准入时的同一成本归还且仅归还一次**
  （`sync.Once` 保护，重复调用安全，不会出现负数或“额度越用越多”）。
- 窗口成本是“**准入即记账**”：短请求完成也不会提前释放速率/突发额度。
- 成本比剩余额度大的请求（例如仅剩 2、本次成本 4）在对应层直接拒绝。

## 2. 分层口径：客户端 → 分组 → 全局

归属分组的请求必须**三层全部通过**才放行；任一层触顶返回独立、可区分的原因：

| 顺序 | 层     | 拒绝原因（`X-Deny-Reason`）     | 含义                       |
|------|--------|---------------------------------|----------------------------|
| 1    | 客户端 | `burst_exceeded`                | 客户端突发窗成本超限       |
| 2    | 客户端 | `rate_exceeded`                 | 客户端速率窗成本超限       |
| 3    | 分组   | `group_burst_exceeded`          | 分组突发窗成本超限         |
| 4    | 分组   | `group_rate_exceeded`           | 分组速率窗成本超限         |
| 5    | 分组   | `group_in_flight_limit`         | 分组在途成本超限           |
| 6    | 全局   | `global_exceeded`               | 全局在途成本超限           |

- 分组配置：`groups.<name>` 各自有 `rate_per_sec` / `burst` / `in_flight`，
  窗口长度与客户端层一致（速率 1s，突发取全局 `burst_window_ms`）。
- 归属关系：`client_groups.<client> = <group>`，或请求显式携带分组
  （HTTP 头 `X-Group-ID`）。解析不到/指向未知分组的请求**不经过分组层**，
  仍正常经过客户端层与全局层（允许分组与映射分阶段上线）。
- **隔离性**：分组状态相互独立、也与无分组请求独立。某个分组超额只会拒掉
  本组请求，不影响其他分组，也不会误伤全局内本来正常的请求；
  分组触顶不会提前消耗全局名额（先分层判定、全部通过后一次性记账）。
- 熔断判定仍在额度之前：熔断打开时快速失败，不占用任何层的成本额度。

## 3. 运行期调整：`Guard.UpdateConfig` / SIGHUP 热加载

### 3.1 校验与回退

- `UpdateConfig(cfg)` 先做**完整校验**（与启动时同一套 `Config.Validate`）：
  字段为 0/负、`burst > rate`、成本非正、空键、未知字段、重复 JSON 键等
  一律明确报错。
- 校验失败：**返回错误并继续沿用旧配置**，服务与在途请求完全不受影响。
- 命令行进程：给配置文件路径启动（`-config`）后，向进程发 `SIGHUP`
  即可重读文件并热换配；文件非法时记录错误日志并保持旧配置。

### 3.2 切换边界（确定且可复现）

- 限流器的“**取配置快照 → 多层判定 → 记账 → 归还**”与换配共用同一把互斥锁：
  一个请求要么完整按旧配置核算，要么完整按新配置核算，不存在半新半旧的判定。
- **已受理未结束的请求**：其 `client/group/成本` 在准入时刻已固化进 lease，
  仍按原口径跑完上游并精确归还、只归还一次；不重复计费、不静默丢弃，
  也不会因为配置里移除了某分组或改了成本而受影响。
- **缩容不追溯**：新上限只约束换配“之后”的准入判定；换配时刻已在窗口内/
  在途的成本保持原样，随窗口滑出或请求结束自然收敛。因此缩容后短时间内
  在途成本可能瞬时高于新上限，这是允许的确定行为（只挡新请求）。
- **成本/映射变更**：历史窗口条目携带准入时的成本；换配后新请求按新成本、
  新归属核算。
- **分组移除**：被移除且无在途成本的分组状态立即清除；仍有在途的分组保留
  状态直到其请求按原口径结算完毕。
- **熔断器**：换配只更新阈值与冷却时长，不主动打开/关闭熔断；
  open 到期时刻不被重置，阈值用于之后的连续失败比较。

## 4. 配置示例

```json
{
  "rate_per_sec": 100,
  "burst": 20,
  "burst_window_ms": 100,
  "global_in_flight": 1000,
  "failure_threshold": 5,
  "open_cooldown_ms": 5000,
  "upstream_timeout_ms": 2000,
  "endpoint_costs": { "/report/export": 8, "/report/query": 2 },
  "groups": {
    "tenant-a": { "rate_per_sec": 40, "burst": 10, "in_flight": 200 },
    "tenant-b": { "rate_per_sec": 60, "burst": 15, "in_flight": 300 }
  },
  "client_groups": { "client-1": "tenant-a", "client-2": "tenant-a" }
}
```

所有新增字段缺省为空/缺省语义，旧配置文件无需改动即可继续运行。

## 5. 验证方法

```bash
# 全量测试（含 -race 并发核算验证）
go test ./... -race -count=1

# 仅看新增能力
go test ./... -run 'Weighted|Group|UpdateConfig|Enriched|GuardServeRequest' -v
```

覆盖点：

- **成本加权**：混跑成本 1/2/4 时任意窗口不超额；成本大于剩余额度整体拒绝、
  拒绝不扣额度；成功受理结束精确归还且只归还一次；并发洪峰全局在途不超上限、
  最终归零（`cost_test.go`）。
- **分组分层**：组内三种分组拒绝原因可区分；一个分组打满不影响其他分组与
  无分组请求；组间高并发各自只归因于自己（`group_test.go`、
  `guard_integration_test.go`）。
- **运行期调整**：非法配置报错且旧配置继续生效；缩容只约束换配后的判定、
  不追溯历史记账；换配时在途请求按原成本收尾、不重不漏；并发换配与准入
  交替时“受理时刻不超当时上限”（`reload_test.go`）。
- **配置解析**：新字段解析/缺省成本/未知分组映射；各类非法富配置被拒绝
  （`config_new_test.go`）。
- **既有回归**：原有客户端限速、突发恢复、全局上限、熔断、优雅收尾用例保持通过。

手动验证热加载：

```bash
go run ./cmd/traffic-guard -config config.json -listen :8080
# 修改 config.json 后
kill -HUP <pid>     # 日志出现 "config reloaded and applied without restart"
# 写入非法配置后再 SIGHUP：日志报错，服务继续沿用旧配置
```
